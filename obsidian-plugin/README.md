# Fomo × Obsidian 开发状态

目标是在 Obsidian 的 Fomo 专用文件夹中双向同步，并提供 Fomo 卡片流、快速记录、引用和回顾。

Obsidian 端不再重复实现 Fomo AI 会话。用户已经安装的 Claudian 会把整个 Obsidian 库作为代理工作目录，可以读取、搜索和修改同步到 Fomo 专用文件夹的 Markdown；需要明确限定背景时，可在 Claudian 输入框中使用 `@Fomo/` 引用整个专用文件夹，或使用 `@Fomo/笔记.md` 引用单条笔记。打开某条同步笔记后，也可以直接围绕当前笔记对话。Fomo 桌面版现有 AI 保留，供不依赖 Obsidian 的场景使用。

这里的“可访问”不表示每次对话都会自动把全部笔记塞进模型上下文。Claudian 以库为工作目录，代理可按任务检索；明确引用文件夹或笔记能让会话范围更可控。Fomo Cards 不保存 Claudian 的供应商配置、API 密钥或会话数据，也不向 Claudian 注入第二套聊天界面。

插件源码提供卡片流、快速记录、搜索、原位编辑、引用关系及每日回顾。回顾只选当天之前的笔记，支持在 Obsidian 内设置数量、时间和标签范围、标记已回顾以及写下联想。回顾设置独立保存；已配对的回顾标记可在桌面设置中手动预览并合并。插件侧删除明确使用 Obsidian 库内回收站，并保留删除保护记录。卡片可显示正文内部链接、`fomo_references`、批注来源和联想来源对应的引用与被引用；旧批注 ID 和原始导入标识仍需人工处理。卡片流只识别含有效 `fomo_id` 和 `fomo_created` 的 Markdown 文件。

以上为开发工作区中的实现和隔离测试结果，不代表插件已安装或已连接到用户的实际知识库。Claudian 只能访问实际存在于其可用工作范围内的文件；仍只保存在 Fomo 桌面数据里的笔记，必须先通过已完成并验证的同步路径写入专用文件夹。

开发版桌面设置提供实验性的手动预览、部分纯文字和 Fomo 管理图片同步，以及可处理的纯文字冲突比较。执行前创建保护副本并校验预览；尚无后台自动同步。已有文件的回写通过插件原子比较替换。Obsidian 插件中有确认记录的删除可预览并移入 Fomo 回收站；配对插件支持受保护删除时，Fomo 中的删除也可预览并移入 Obsidian 库内回收站。重命名和移动按 ID 识别，文件消失本身不会触发删除。这些能力尚未经过真实 Obsidian 隔离库验收，不能视为完整双向同步。

普通文字即使带 Fomo 编辑器生成的段落或换行 HTML，也可在 HTML 与正文严格一致时同步；Obsidian 修改会维持原有段落或换行形式，更新对应 HTML 并保留 Fomo 旧版本。配对连接可同步 Fomo 管理的 PNG、JPEG、GIF 和 WebP 图片，文件按内容哈希保存在专用文件夹的 `Fomo-assets` 内，卡片流会验证后显示。图片记录位于 Fomo YAML 属性中，普通 Obsidian Markdown 编辑器当前不会自动显示这些图片；任意 Markdown 图片链接、音视频、格式化 HTML 和不支持的结构仍需人工处理。

不要把 Fomo 自身数据目录下 Memos 当成可写同步目录。现有 Markdown 是派生文件，外部编辑可能被后续生成覆盖。

桌面端仅接受含标准 `.obsidian` 配置目录的库内可见子文件夹；不能选择整个库、库外路径或隐藏目录。配置目录不是 `.obsidian` 的特殊库暂不支持该校验，不能通过桌面同步入口。

当两边各有不冲突的变更时，同步预览只显示当前批次，并提示剩余数量。执行后需重新选择文件夹检查下一批；各批会重新校验状态和创建保护备份。存在冲突或尚不支持的删除时仍会停止，已有文件的覆盖尚需 Obsidian 原子操作接口。

删除规划要求凭据同时包含笔记 ID、事件 ID 和与当前同步基线一致的文件内容哈希；单独的 ID、旧版本哈希或文件消失本身都不会触发删除。已确认的插件删除可通过手动预览同步到 Fomo 回收站；Fomo 向 Obsidian 的删除也需配对支持回收站保护和删除凭据的插件，并逐项预览执行。

Obsidian 原生删除没有插件保护凭据时，桌面预览在满足安全检查且不存在其他类型冲突时，可逐条展示缺失笔记的 Fomo 摘要供人工核对；其他新增或编辑操作会在核对后重新预览。多条缺失笔记需要分别确认。用户确认该文件确实已在 Obsidian 删除后，Fomo 会先备份并将自己的副本移入回收站。此路径无法自动证明 Obsidian 文件位于回收站；若只是移动、同步延迟或目录不可用，应取消操作。若执行中断，待处理记录可在重新预览后恢复。

如果一条删除有插件凭据，另一条只是缺失，前者可以单独执行；后者仍需重新预览和人工核对。其他类型的冲突仍会阻止执行。

规划器忽略清单中已消费的删除事件 ID；从插件向 Fomo 同步删除时会保存待处理意图和已消费事件，并在异常后要求重新检查。清单被回滚等场景仍需要人工核对保护副本。

从插件卡片删除时，先在插件数据中保存原文和待确认记录，再调用 Obsidian 的回收站，成功后标记记录。记录失败不会开始删除；回收站结果不明时会保留待确认记录并阻止重复操作。配对桥接只读取当前专用文件夹已确认记录的标识和哈希，不传输原文。检查后到回收站调用之间仍存在并发窗口，尚不能视为完整的双向删除协调。插件数据中包含删除前的私有笔记原文，应和知识库一样保护，不应提交到 Git。

插件设置中的“待确认的删除”可在原位置仍存在相同 ID 和创建时间的笔记时，手动取消待确认状态；原始保护副本保留，不发送删除凭据。删除期间捕获到的编辑器内容会显示在保护记录中。原位置没有笔记或身份不匹配时必须先人工检查回收站；桌面同步设置提供凭据核对，只有记录一致时才会完成待处理同步。

插件侧已实现仅限专用文件夹、校验笔记身份和原文未变化的 `replaceSyncedFile` 操作。开发版提供手动连接：在插件设置中开启连接，复制一次性配对码到 Fomo 的存储设置，再选择同一个专用文件夹进行检查。桥接只监听本机回环地址，使用内存中的随机密钥，并校验文件夹身份；不会自动启动。隔离联调覆盖鉴权和文件安全写入；配对界面和真实 Obsidian 行为尚未实机验收，断线恢复仍需完善。

新建和原位编辑框可以通过“@ 引用笔记”搜索专用文件夹中的笔记并插入 Fomo 内部链接。重复 ID 不提供选择；原位编辑会排除当前笔记；目标或草稿在选择期间发生变化时需要重新选择。

原位编辑草稿按知识库路径、专用文件夹和笔记 ID 隔离；保存或取消时不会清除其他窗口更新过的草稿。旧版按 ID 保存的草稿没有知识库信息，不会自动载入；界面会提供手动取回入口，需先确认它属于当前笔记。

已配对插件时，同步预览可登记普通 Markdown，包括通过校验的已有 YAML 属性：先备份并经插件核对原文与 ID 后添加身份信息，再重新预览并导入 Fomo。两批操作均需手动执行；自定义属性及注释保留在 Obsidian 文件中，正文导入 Fomo。格式含糊、重复属性、YAML 合并键和不一致的换行等情况仍会拦截；真实 Obsidian 实机验收尚未完成。

## 隔离测试用插件文件

实际 Obsidian 的插件加载器不支持此插件入口中的相对模块引用。运行 `node scripts/build-obsidian-plugin.cjs` 生成可加载的 `work/obsidian-plugin-package`，其中的 `main.js` 已打包依赖；不要直接把源码目录的 `main.js` 当成可安装入口。

Obsidian 插件目录的名称为 `fomo-cards`，其运行文件来自本目录下的 `fomo/`：`manifest.json`、`main.js`、`styles.css`、`sync-bridge.cjs`、`frontmatter.cjs`、`image-assets.cjs` 和 `LICENSE-js-yaml.txt`。这些文件必须作为一组保留；`data.json` 和任何用户笔记都不是分发文件。

使用 Node 24 在项目工作区运行 `npm run test:obsidian-package`，会先生成共享模块，再检查插件目录内容、语法和捆绑模块。该检查不是 Obsidian 实机验收，也不会安装插件或改动知识库。只有在隔离库完成实际使用验证之后，才应考虑正式安装或发布。
