# Fomo

**持续记录，保持思考。**

Fomo 是一款面向 Windows 的本地优先卡片笔记应用。你可以用它记录一闪而过的想法，用标签整理线索，通过引用和批注连接笔记，再在回顾中重新发现过去的记录。

它为桌面上的日常记录而设计：打开输入窗口写下几句话，内容保存在本机；需要整理时，再通过搜索、标签、时间和笔记之间的关系找回它们。

项目借鉴了卡片笔记的记录方式与部分交互，并围绕本地存储、备份和桌面使用进行开发。Fomo 是独立项目。

> **项目状态：** Fomo 仍在开发中。当前源码版本为 **1.0.62**；安装包和版本说明以 [Releases 页面](https://github.com/tanyaoo/Fomo/releases)为准。源码功能与已发布安装包不一定完全相同。

## 下载安装

前往 [Fomo Releases](https://github.com/tanyaoo/Fomo/releases)，选择 Windows x64 版本：

| 文件 | 适合的使用方式 |
| --- | --- |
| `Fomo-<版本>-x64.exe` | 安装版。运行安装程序，按提示选择安装位置。 |
| `Fomo-<版本>-x64.zip` | 压缩包版本。解压后运行程序。 |

安装版支持检查更新，更新时需要连接发布服务。安装提示和更新行为请以 Windows 与对应安装包的实际显示为准。

首次使用建议先写几条测试笔记，熟悉标签、搜索和备份流程；导入已有资料前，保留一份原始备份。

## 功能介绍

### 记录想法

- 使用卡片笔记记录文字，编辑器提供标签、图片、文本格式和列表等工具。
- 从系统托盘打开新建笔记窗口，减少切换窗口的步骤。
- 在笔记列表中原位编辑，也可以打开独立笔记窗口继续阅读和修改。
- 使用浮窗保留需要随时查看的笔记。

### 找回与整理

- 用 `#标签` 和多级标签组织内容。
- 通过关键词、时间、标签和媒体类型筛选笔记，也可以查看收藏和回收站。
- 在图片视图中浏览带图片的记录。
- 查看热力图、记录数量和其他统计信息。

### 连接与回顾

- 在笔记中引用其他笔记，或围绕原笔记添加批注。
- 查看引用、被引用和相关笔记，沿着已有记录继续阅读。
- 使用每日回顾和随机漫步重新浏览过去的想法。
- 查看笔记历史版本；恢复前会显示确认步骤。历史版本主要记录文字内容，图片和音频不作为历史版本内容展示。

### 保存与分享

- 笔记保存在本机，支持查看数据位置、存储占用和备份。
- 导入兼容格式的笔记备份，或导出备份、Markdown 和离线 HTML。
- 选择分享图片模板，生成适合保存或分享的笔记图片。

不同版本的功能和界面可能有所差异，请以已安装版本为准。

## 开始使用

### 1. 写下一条笔记

打开 Fomo，在顶部编辑器输入内容，然后发布。短句、链接、清单或一段完整想法都可以单独成为一条笔记。需要快速记录时，也可以通过托盘入口或快捷键打开新建窗口。

### 2. 添加标签

在正文中输入标签，例如 `#阅读` 或 `#工作/计划`。标签会出现在侧边栏，可用于浏览同一主题下的记录；多级标签适合在主题逐渐变多后继续细分。

### 3. 引用或批注已有笔记

在编辑器中选择已有笔记进行引用，或从笔记菜单进入批注。建立关系后，可以在笔记的关系区域继续查看来源和被引用的内容。

### 4. 搜索与回顾

使用搜索框查找正文和标签，或按时间、标签及媒体类型缩小范围。想重新看看过去的记录时，可以打开每日回顾或随机漫步。

### 5. 建立备份习惯

打开 **设置 → 存储与备份**，检查当前数据位置及自动备份设置；也可以手动导出备份，并另存到其他磁盘或位置。更换设备、迁移目录或批量导入前，建议先确认备份可用。

## 导入、导出与备份

### 从兼容备份导入

Fomo 支持读取兼容格式的 ZIP、HTML、CSV 或已解压文件夹。可在 **设置 → 导入导出** 中选择文件或文件夹，查看预览并选择重复内容的处理方式。导入采用合并方式，建议按以下顺序操作：

1. 先保留原始备份文件，同时备份现有 Fomo 笔记。
2. 在导入预览中检查待导入数量、重复项及附件提示。
3. 确认导入后，抽查正文、标签、图片和其他附件。

仓库当前实现会报告检测到的缺失附件；已发布版本的提示内容以实际界面为准。导出文件没有包含的附件无法恢复。本地读取还有大小限制：文件夹或 ZIP 中单个附件上限为 24 MB、累计附件上限为 120 MB，超过限制时导入会暂停并提示；单个导出文件超过 1 GB 也会拒绝读取。

### 导出和恢复

- **备份：** 可导出备份文件，也可在设置中查看和预览本地备份后恢复。
- **Markdown：** 支持将笔记导出为 Markdown；数据目录中的 Markdown 副本是应用生成的只读派生文件，目前不支持与 Obsidian 双向同步。
- **Obsidian 实验功能：** 开发版提供专用文件夹的手动同步预览及配套插件，覆盖部分文字和受支持的图片；没有后台自动同步，冲突、删除和部分格式仍有限制，且真实 Obsidian 隔离库验收尚未完成。请先备份并阅读 [开发状态与限制](obsidian-plugin/README.md)，不要把 Fomo 数据目录的派生 Markdown 当作可写同步目录。
- **离线 HTML：** 可导出 HTML，供离线浏览。

自动备份通常仍与原数据位于同一设备或数据目录；磁盘损坏时，它未必能替代异地备份。请根据资料的重要程度，定期保存外部副本并验证恢复。

## 数据与隐私

- 笔记、草稿和附件保存在本机；当前没有手机同步或云端笔记同步。
- 默认用户目录为 `%APPDATA%\Fomo`，默认笔记数据目录为 `%APPDATA%\Fomo\data`。如果已有旧版本数据，实际目录可能受迁移结果或自定义设置影响，请以应用中的 **设置 → 存储与备份** 为准。
- 可以在设置中查看或更换数据位置。使用外接磁盘或自定义位置时，请保证目录在启动应用时可访问。
- 本地保存图片时保留原图；导入包中缺失的附件不会自动补全。
- 备份文件可能包含笔记和草稿，请像保护原始数据一样保护备份。
- 检查更新需要网络连接；使用外部 AI 服务时，请求中使用的内容会发送到所配置的服务提供方。

## AI 功能

Fomo 提供可选的 AI 设置，可填写 API 地址、模型和 API Key。当前实现通过兼容 `/chat/completions` 的接口发送请求；默认配置指向 DeepSeek。使用前需要启用服务、保存有效配置，并自行确认服务提供方的费用及数据处理方式。

应用使用系统加密能力保存 API Key；系统加密不可用时，应用不会把 Key 作为明文保存。当前 AI 搜索尚未接入，其他 AI 功能的可用性以安装版本、配置和服务响应为准。

## 从源码运行

### 环境要求

- Windows x64
- Node.js 24 或更高版本，以及 npm

在仓库目录安装锁定的依赖并启动桌面应用：

```powershell
npm ci
npm start
```

其他常用命令：

```powershell
npm run build             # 构建单文件页面
npm run dev               # 启动桌面开发预览
npm run preview:sidebar   # 启动本机浏览器交互预览
```

普通桌面开发启动默认可能读取本机 Fomo 数据。若要使用隔离数据，可在 PowerShell 中为当前终端单独指定测试目录：

```powershell
$env:MEMOFLOW_DATA_DIR = Join-Path $env:TEMP "Fomo-Dev-Data"
npm start
```

该环境变量只影响当前终端及由它启动的未打包应用。请使用专门的测试目录，避免把真实笔记用于自动化测试。

浏览器交互预览会从本地笔记库读取初始数据；预览中的编辑保存在内存，不写回桌面笔记库，关闭服务后不会保留。服务绑定本机地址，访问地址包含令牌，不要把地址分享给他人。

## 测试与打包

```powershell
npm test                  # Node 单元测试
npm run test:desktop      # 桌面应用冒烟测试
npm run preview:studio    # 使用隔离数据进行视觉检查
npm run dist:win          # 构建 Windows 安装包和 ZIP
```

项目使用 `.nvmrc` 固定的 Node 24 版本。首次构建请运行 `npm ci`，再运行 `npm test` 和 `npm run dist:win`。安装包输出到 `release/`。针对特定模块，也可以运行 `npm run test:settings`、`npm run test:editor`、`npm run test:workspace` 或 `npm run test:exports`。桌面相关测试需要可运行 Electron 的环境。

Windows 正式发布默认要求代码签名。可使用证书或 Azure Trusted Signing；如果暂时接受未签名安装包，必须显式设置仓库变量 `MEMOFLOW_ALLOW_UNSIGNED_RELEASE=true`。未签名的安装包会显示未知发布者，不能标记为已签名版本。

## 项目结构

```text
desktop/    Electron 主进程、窗口、存储、备份和系统集成
dist/       应用界面、共享逻辑、样式和运行资源
src/        编辑器与部分界面模块源码
scripts/    构建、预览、打包与专项检查脚本
tests/      Node 测试及测试夹具
obsidian-plugin/  实验性 Obsidian 插件源码及限制说明
```

仓库同时包含 `src/` 源码和 `dist/` 运行资源；修改前请先确认对应模块的构建方式。开发、测试和提交时，请勿把个人笔记、草稿、附件、私有截图、API Key 或其他凭据放进仓库或构建包。

## 常见问题

**换电脑后如何带走笔记？** 先在旧设备导出备份，保存到安全位置；在新设备安装 Fomo 后，通过设置中的导入或备份恢复流程操作。恢复前请阅读预览和确认提示。

**为什么导入后有图片缺失？** 请先检查原始导出包是否包含对应附件，以及导入预览中的提示。单独选择 HTML 或 CSV 文件时，如果附件没有随文件一起提供，应用无法自动找回。

**可以把 Markdown 文件交给 Obsidian 双向编辑吗？** 目前不支持。Fomo 生成的 Markdown 是派生副本，不能作为与 Obsidian 双向同步的依据。

**为什么 GitHub 上的界面和安装包不同？** `main` 可能包含尚未打包发布的更新。请对照应用内显示的版本号和 Releases 页面查看对应版本。

**开启 AI 后会联网吗？** 会。调用 AI 时，应用会向你配置的服务发送请求；没有配置服务时，本地记录、搜索和备份等功能仍可使用。
